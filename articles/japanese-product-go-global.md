2022年、上海のオフィス。私たちのチームは「良いプロダクトを作れば世界が勝手に見つけてくれる」と本気で信じていた。

3ヶ月後、現実を知った——プロダクトの質と、海外で見つけてもらえるかは、まったく別の問題だ。（この当たり前のことを、痛みを伴って理解するのに数ヶ月かかった）

その後、AFFiNEをCOOとして0から60,000スター・Product Hunt #1を30回まで導いた。本記事では、その経験から「日本発のプロダクトが英語圏で伸びるための実践フレーム」を書く。日本のSaaSやOSSは技術力が高いのに、海外露出で損をしているケースが本当に多いからだ。

## Key Stats

| 指標 | 数値 |
|------|------|
| GitHubスター（0→） | 60,000+ |
| Product Hunt #1 | 30回 |
| GitHub Trending登場 | 28回（5ヶ月） |
| 支援したAIスタートアップ | 150社以上 |

## なぜ日本発プロダクトは海外で埋もれるのか

理由は技術力ではない。ほぼ常に「見せ方」と「届け方」だ。

- **言語の壁**：英語のREADMEやLPが「翻訳された英語」になっていて、海外エンジニアが3秒で違和感を覚える
- **マーケティングの文法の違い**：日本式の謙虚な訴求は、英語圏の「What is this? Why better?」を即答する文化と噛み合わない
- **配信の不在**：良いものを作って終わり。英語圏の開発者が集まる場所（HN・Reddit・PH）に出していない

逆に言えば——この3つを直すだけで、同じプロダクトの海外での見え方は劇的に変わる。

## 海外展開の前に決める3つのこと

具体的な施策に入る前に、これだけは固める。

1. **ICP（誰に刺すか）を1文で**：「世界中の開発者」ではなく「セルフホストしたい個人開発者」のように狭く
2. **ポジショニングを1行で**：`[カテゴリ] + [差別化] + [対象]`。例「Gitでバージョン管理できるローカルファーストなNotion代替」
3. **主戦場を1つに**：PLG型ならPH/GitHub、技術的深さで勝負ならHacker News。全部に薄く出さない

## 英語圏で効く4つの入口

| チャネル | 向いているもの | 一言 |
|------|------|------|
| GitHub / Trending | OSS・開発者ツール | スター速度で載る。READMEが命 |
| Product Hunt | 完成度の高いSaaS・アプリ | 1日の集中投票。事前の温め必須 |
| Hacker News（Show HN） | 技術的に面白いもの | 信頼を得る場所。正直さが武器 |
| Reddit | ニッチコミュニティ向け | 宣伝色を消し、価値提供から入る |

ポイントは**同じ日に分散させず、波（wave）として連鎖させる**こと。温かい層→コミュニティローンチ→二次拡散、の順で動かすと、各イベントの小さなスパイクが累積して週間Trendingに載りやすくなる。

## ローカライズの落とし穴

- **機械翻訳のままの英語コンテンツはNG**。最低でもネイティブレビューを通す
- **READMEの最初の画面を「変換ページ」として作る**：何ができるか・誰向けか・なぜ良いかを5秒で
- **Build in public**：作っている理由・失敗・意思決定をオープンに共有する。英語圏のエンジニアはこの「過程の透明性」に強く反応する

（AFFiNEのREADMEは3回作り直した。最初のバージョンは技術者に寄りすぎて、一般エンジニアに刺さらなかった）

## 体験：AFFiNEが使った出海の順序

1. **READMEとポジショニングを英語ネイティブ基準で作り直す**
2. **温かい層に事前告知**（既存フォロワー・コミュニティ）
3. **コミュニティローンチ**（HN Show HN → Reddit関連サブ → PH を数日でつなぐ）
4. **二次拡散**（ニュースレター・まとめ記事・マイルストーン報告）
5. **受け皿を用意**（Discord・good first issue・CONTRIBUTING）

この順序を回すたびにベースラインが上がり、次のスパイクでまたTrendingに押し戻される——この「サイクル設計」が28回のTrending登場を生んだ。

## まとめ

日本発プロダクトの海外展開は、技術の問題ではなく**見せ方と届け方の設計**の問題だ。ICPと一行ポジショニングを固め、主戦場を1つに絞り、波として連鎖させ、ネイティブ基準でローカライズする——これだけで、埋もれていたプロダクトは見つけてもらえるようになる。

## よくある質問（FAQ）

### 日本発のプロダクトが最初に出すべき海外チャネルはどこですか？

プロダクトの形で決めます。OSS・開発者ツールなら**GitHub + Hacker News（Show HN）**から。技術的に面白ければHNで信頼を得られ、それがGitHubスターに変わり、スターがTrendingに乗せ、Trendingがさらに露出を生む——という連鎖が作りやすいからです。完成度の高いSaaS・アプリならProduct Huntが向きます。いずれも「全チャネルに薄く」ではなく、1つに集中して波を作ることが鍵です。

### 英語が得意でなくても海外展開はできますか？

できます。ただし「機械翻訳をそのまま出す」のだけは避けてください。日本のエンジニアが変な日本語に一瞬で気づくのと同じで、英語圏のエンジニアも翻訳臭に敏感です。最低限ネイティブのレビューを通すこと、READMEとLPの最初の画面（何ができるか・なぜ良いか）だけでもネイティブ品質にすること。完璧な英語より、明確で正直な英語のほうが刺さります。

### 海外展開でいちばんやってはいけないことは何ですか？

「良いものを作れば見つけてもらえる」と信じて、配信を設計しないことです。英語圏の開発者が集まる場所（HN・Reddit・PH・GitHub）に、適切なタイミングで、適切な見せ方で出す——この設計を省くと、技術力が高くても埋もれます。次に多い失敗は、告知を1週間かけて分散させてしまい、スター速度が出ないこと。集中させることが命です。
